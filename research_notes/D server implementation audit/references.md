# Upstream D implementation evidence

## What evidence supports pointer and allocation decisions?

### Takeaway
The date beside each repository is its latest default-branch commit visible on or before November 21, 2026. The code links identify the exact source snapshot. Dates measure recency, not production adoption or validation of performance.

### Cited Findings
- **dlang/dmd**, default-branch commit [2026-11-21](https://github.com/dlang/dmd/commit/bc9a7a27e3608bf4ae0940a28fec9288cf5a726f). OutBuffer stores a slice and an offset, exports raw C++ accessors as @system, and isolates trusted growth and destruction. Its @nogc reserve can still allocate outside the GC. The compiler’s ownership requirements are specific to this buffer. [storage](https://github.com/dlang/dmd/blob/bc9a7a27e3608bf4ae0940a28fec9288cf5a726f/compiler/src/dmd/common/outbuffer.d#L45-L66), [methods](https://github.com/dlang/dmd/blob/bc9a7a27e3608bf4ae0940a28fec9288cf5a726f/compiler/src/dmd/common/outbuffer.d#L89-L203).
- **dlang/phobos**, default-branch commit [2026-11-17](https://github.com/dlang/phobos/commit/79358d1593b9647a2151dc699c34046f8f74fce8). std.bitmanip offers fixed-size endian conversion with @nogc and a consuming read(ref range). These are precedents for bounded scalar conversion and advancing a slice without owning the input. [endian functions](https://github.com/dlang/phobos/blob/79358d1593b9647a2151dc699c34046f8f74fce8/std/bitmanip.d#L3110-L3168), [range read](https://github.com/dlang/phobos/blob/79358d1593b9647a2151dc699c34046f8f74fce8/std/bitmanip.d#L3816-L3838).
- **libmir/mir-ion**, default-branch commit [2025-11-06](https://github.com/libmir/mir-ion/commit/a5c2a78fd094c752865fcf0af2ddf2b8f2e7de9a). The JSON deserializer accepts scoped input, with a separate overload for a caller-supplied destination. The instantiated output type and error path influence @nogc applicability. Its staged SIMD scanning addresses structural text, a different workload from decoding a few fixed-size packet fields. [input and callback](https://github.com/libmir/mir-ion/blob/a5c2a78fd094c752865fcf0af2ddf2b8f2e7de9a/source/mir/deser/json.d#L16-L51), [scanning](https://github.com/libmir/mir-ion/blob/a5c2a78fd094c752865fcf0af2ddf2b8f2e7de9a/source/mir/ion/internal/stage1.d#L1-L47).
- **libmir/asdf**, default-branch commit [2025-11-06](https://github.com/libmir/asdf/commit/8b3352146256f3d850caa41b25351893fb1b773e). The parser has compiler/architecture-specific SIMD code and explicitly mallocs spill nodes in one path. This is an illustration of a trade-off for structured data, not evidence of zero allocations end to end. [SIMD code](https://github.com/libmir/asdf/blob/8b3352146256f3d850caa41b25351893fb1b773e/source/asdf/jsonparser.d#L24-L47), [spill allocation](https://github.com/libmir/asdf/blob/8b3352146256f3d850caa41b25351893fb1b773e/source/asdf/jsonparser.d#L364-L413).
- **CyberShadow/ae**, default-branch commit [2026-11-01](https://github.com/CyberShadow/ae/commit/7870bc3cd03cd43fce638fcf3cf5a685cadea70a). TData distinguishes wrapping existing GC storage from copying. DataVec supports shifting a prefix and copying into a caller-selected destination. Ownership has to be explicit when a buffer outlives its read operation. [GC wrapping](https://github.com/CyberShadow/ae/blob/7870bc3cd03cd43fce638fcf3cf5a685cadea70a/sys/data.d#L333-L346), [copy to destination](https://github.com/CyberShadow/ae/blob/7870bc3cd03cd43fce638fcf3cf5a685cadea70a/sys/dataset.d#L20-L38), [segmented input](https://github.com/CyberShadow/ae/blob/7870bc3cd03cd43fce638fcf3cf5a685cadea70a/sys/dataset.d#L101-L116).
### Inferences
- A short synchronous decode can borrow the input. A queued or retained payload needs an owner. Merely adding @nogc does not establish zero allocation, pointer validity, or bounded latency. Keep small scalar code until a packet-specific measurement shows a gain.

### Gaps
- No upstream benchmark here measures this emulator. The two Mir repositories showed a compiler maintenance commit just over 12 months before the audit and within the 18-month window. This is weaker evidence of active development than frequent subsystem work.

## What can the networking and game libraries establish?

### Takeaway
The libraries expose different, explicit lifetimes at the I/O boundary. These examples do not decide the emulator’s scheduling or authority model.

### Cited Findings
- **vibe-d/vibe.d**, default-branch commit [2026-11-20](https://github.com/vibe-d/vibe.d/commit/4deed199806b40d8a360b6da9c6f4e37b6ebed40). The REST request filter uses a scoped stream parameter and a scoped callback on the receiving function. [REST boundary](https://github.com/vibe-d/vibe.d/blob/4deed199806b40d8a360b6da9c6f4e37b6ebed40/web/vibe/web/rest.d#L1848-L1856).
- **vibe-d/vibe-core**, default-branch commit [2026-11-20](https://github.com/vibe-d/vibe-core/commit/47e8baf32ab03f1e9d456cf0b023c45c3a5c3d93). The task-level TCP API takes scoped read/write slices and internally adapts to callback completion. Its exposed API and implementation use different escape contracts. [synchronous-looking operations](https://github.com/vibe-d/vibe-core/blob/47e8baf32ab03f1e9d456cf0b023c45c3a5c3d93/source/vibe/core/net.d#L916-L973).
- **vibe-d/eventcore**, default-branch commit [2026-10-29](https://github.com/vibe-d/eventcore/commit/030d5bc6ae193b1d4238efcfce84fbaba25c2518). The proactor interface takes slices and completion delegates and requires completion or cancellation before the next operation of the same direction. This boundary matters when considering sharing a read/write buffer across queued operations. [read/write contract](https://github.com/vibe-d/eventcore/blob/030d5bc6ae193b1d4238efcfce84fbaba25c2518/source/eventcore/driver.d#L274-L312).
- **etcimon/libasync**, default-branch commit [2026-08-19](https://github.com/etcimon/libasync/commit/20c29c20cecd367ff38bf4cf9d7f210cd97c04ac). Its read-ready handler drains into a caller-provided buffer. Its send explicitly tracks short sends on POSIX. This is a concrete event-driven alternative, with no measured advantage for this emulator. [transport implementation](https://github.com/etcimon/libasync/blob/20c29c20cecd367ff38bf4cf9d7f210cd97c04ac/source/libasync/tcp.d#L154-L180).
- **gecko0307/dagon**, default-branch commit [2026-11-18](https://github.com/gecko0307/dagon/commit/bb88e715e9a0adee154f9c41c10c4e4a3f00d869). The ENet extension forms a slice over native packet bytes and copies the receive data for its message. The pointer at that boundary is intentional. Evidence applies to implementation only. [receive handling](https://github.com/gecko0307/dagon/blob/bb88e715e9a0adee154f9c41c10c4e4a3f00d869/extensions/network/src/dagon/ext/network/package.d#L229-L248).
### Inferences
- Preserve the emulator’s simpler ownership model wherever current consumers complete synchronously. Sharing payloads between senders and recipients requires checking exactly where each write completes, who mutates headers, and when storage is reused. A callback or fiber rewrite needs independent emulator measurements.

### Gaps
- These sources provide no comparison of MMO tick scheduling, entity representation, or persistent-world rules. No quantitative libasync/fiber overhead claim is justified here.

## How should performance and lifetime claims be checked?

### Takeaway
Use warm-up and representative inputs, record thread-local GC allocation separately from process-wide pauses, and qualify claims by workload.

### Cited Findings
- **leotada/andaime**, default-branch commit [2026-11-09](https://github.com/leotada/andaime/commit/e2be37bcb19fc47dba2e8be0aa0730041309c1eb). The project documents @safe and DIP1000. Its routing test prewarms 100 iterations and compares GC.allocatedInCurrentThread across 100,000 executions with a response assertion. That test measures a specific warmed handler on one thread. [safety model](https://github.com/leotada/andaime/blob/e2be37bcb19fc47dba2e8be0aa0730041309c1eb/README.md#L206-L215), [measured loop](https://github.com/leotada/andaime/blob/e2be37bcb19fc47dba2e8be0aa0730041309c1eb/tests/alloc/hot_path.d#L20-L46).
- **alex-1974/concurrency-d**, default-branch commit [2026-10-27](https://github.com/alex-1974/concurrency-d/commit/cab3bb7d5c84169665b752a0b5e241aff3156df5). The public submission API documents @system capture-lifetime responsibility. Its qualification document specifies hardware, compiler, two CPU kernels, paired runs, and a failed earlier stratum as well as the passing independent sample. [safety contract](https://github.com/alex-1974/concurrency-d/blob/cab3bb7d5c84169665b752a0b5e241aff3156df5/README.md#L6-L24), [qualification scope](https://github.com/alex-1974/concurrency-d/blob/cab3bb7d5c84169665b752a0b5e241aff3156df5/docs/M0-PERFORMANCE-QUALIFICATION.md#L1-L20).
- Druntime specifies support for interior pointers and permits implementations to ignore unaligned pointers. GC.ProfileStats separates collection time, thread-pause time and maximum pause. GC.allocatedInCurrentThread is cumulative GC allocation on the calling thread. [pointer representation](https://github.com/dlang/dmd/blob/bc9a7a27e3608bf4ae0940a28fec9288cf5a726f/druntime/src/core/memory.d#L53-L102), [collection metrics](https://github.com/dlang/dmd/blob/bc9a7a27e3608bf4ae0940a28fec9288cf5a726f/druntime/src/core/memory.d#L248-L271), [allocation counter](https://github.com/dlang/dmd/blob/bc9a7a27e3608bf4ae0940a28fec9288cf5a726f/druntime/src/core/memory.d#L1082-L1102).
- For D language semantics, consult the [GC specification](https://dlang.org/spec/garbage.html), [function lifetime attributes](https://dlang.org/spec/function.html#scope-parameters), and [druntime statistics API](https://dlang.org/library/core/memory/gc.profile_stats.html).
### Inferences
- Sample allocation on each producing thread. Record p50/p95/p99 tick durations and overruns in the release configuration alongside collection-count and total-pause deltas. maxPauseTime is a cumulative maximum, not a percentile. Also measure bytes copied, queue depths, connected/visible entities and CPU time. A process-wide pause maximum alone cannot diagnose a slow tick. Start with one warmed packet or fanout workload and preserve output equivalence.

### Gaps
- andaime and concurrency-d illustrate methodology only. C allocator traffic, stack traffic and allocations on other threads are outside a single-thread GC byte counter. No result from these projects proves the emulator needs pooling, manual memory, proactors, SIMD, or parallel game updates.
