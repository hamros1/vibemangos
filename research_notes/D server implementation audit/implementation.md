# D implementation and runtime costs

## Where would a small change buy safety or simplicity?

### Takeaway

Keep the simulation architecture. Tighten two generic trusted interfaces which currently promise more than their type signatures can enforce. One low-risk implementation cleanup is confirmed by the compiler.

### Cited findings

- **Frozen data.** The allocator returns unscanned, process-lifetime native memory. Recursive copying places nested arrays there too. After freezing, lookups restrict indirect values to const, but the public edit method returns mutable V* and registers only the bytes of the outer V. A GC-backed reference assigned to a field in a separately allocated, nested arena array is invisible to that registered range. The top-level string replacement test exercises a different case. Public frozenCopy also returns a mutable result for mutable input, with no registered range. This is a generic API correctness finding. I found no demonstrated failure in a production edit. Preserve stable addresses for current borrowers. Make raw arenaAllocate and frozenCopy private (only module-local users found). For post-freeze edits requiring mutable nested reference-bearing elements, deep-copy the editable children to traced GC storage before exposing them, or explicitly restrict the editing interface to supported row shapes. A type-level rejection test for unsupported shapes is sufficient if production never needs these edits. Narrowing the raw API alone does not fix edit. [Allocator and deep copy](/home/hampus/dmangos/source/dmangos/frozen.d:52) [nested storage](/home/hampus/dmangos/source/dmangos/frozen.d:130) [edit](/home/hampus/dmangos/source/dmangos/frozen.d:319) [tests](/home/hampus/dmangos/source/dmangos/frozen.d:497)
- **Input type qualifications.** Public trusted plain-data decode takes an unconstrained ref T, removes const/immutable from the destination and writes through that pointer. Recursion repeats the operation on qualified struct fields. The legitimate job is initializing a freshly owned result, including immutable string payloads. Return a freshly constructed value, preserving field qualification, or restrict the public destination to writable compatible types and isolate the exceptional initialization in a private helper whose storage the implementation owns. Preserve the existing byte layout so logs and service messages remain compatible. Confirm compile-time cases for qualified targets. Also check lengths in the codec's own encoding before new E[count] for fixed-width elements (the current comparison treats all elements as one byte); avoid changing log format to do this. [Decoder](/home/hampus/dmangos/source/dmangos/plaindata.d:92) [allocation](/home/hampus/dmangos/source/dmangos/plaindata.d:115) [cluster service caller](/home/hampus/dmangos/source/dmangos/cluster/services.d:252) [packet codec precedent](/home/hampus/dmangos/source/dmangos/serialization.d:162)
- **Import the dependency directly.** DMD 2.114.0 reports four deprecations for qualified references to dmangos.world.updatefields in context.d at 3935, 3951, 3952 and 3990. A static import of the module, or local selective imports and short names, resolves the dependency explicitly. This is a direct compiler diagnostic on the audited working copy. [First use](/home/hampus/dmangos/source/dmangos/world/context.d:3935)
- **Optional maintenance.** TcpServer accepts null maintenance by default. Its timeout always counts down from lastMaintenance, which it advances only inside the non-null branch. A client using that supported default polls with zero timeout after the first interval, including while idle. Advance the periodic deadline independently of the optional callback. Both shipping mains supply a callback; priority is low for the current binaries. [Constructor](/home/hampus/dmangos/source/dmangos/net/server.d:224) [loop](/home/hampus/dmangos/source/dmangos/net/server.d:291) [auth caller](/home/hampus/dmangos/source/dmangos/auth/main.d:104) [world caller](/home/hampus/dmangos/source/dmangos/world/main.d:355)

### Gaps

The agent reviewed source and compiler evidence. No malformed input or exploit was exercised. Owner input needed on post-startup edits and reload frequency. Removing a frozen row rebuilds the table and explicitly leaves old borrowed addresses with old contents; the permanent arena and registered ranges can retain memory across repeated rebuilds. Measure repeated GM reloads if this is a supported workload. [Removal](/home/hampus/dmangos/source/dmangos/frozen.d:352)

## What accounts for allocation, pauses and latency?

### Takeaway

The highest-confidence *new* allocation lead is the player tick bookkeeping. Serialization and the socket receive path also allocate, but their ownership requirements differ. Byte counts from a reproduction of two container operations are available, in addition to the repository's earlier end-to-end data.

### Cited findings

- Every maps phase clears and rebuilds a bool[ulong] and materializes maps.values, instanceMaps.values and online.values. playersNow reserves and fills a fresh Inhabitant[] per populated map. The comments document relocation and logout during callbacks. Preserve once-per-tick behavior and mutation-safe snapshots. A DMD 2.114.0 x86-64 microbenchmark using -O -release, 500 preexisting keys and 100 warmed iterations measured **8,000 bytes/iteration** for clearing and refilling this set and **4,096 bytes/iteration** for .values on a 500-element class-reference AA, with GC.allocatedInCurrentThread sampled immediately around each operation. These are isolated operations, not measured worldserver totals or predicted savings. Instrument mapsPhase first. If significant, fill caller-owned scratch buffers for the snapshots and clear stale references after use. The direct foreach around a callback that can delete or move participants would lose correctness. A tick generation on the player could avoid the set but needs a proven stable identity across a tick and migration; do not introduce it on these microbench results alone. [Tick](/home/hampus/dmangos/source/dmangos/world/context.d:6243) [snapshot](/home/hampus/dmangos/source/dmangos/world/map.d:1876)
- Weather snapshots all zone keys each tick when nonempty so it can remove expired unoccupied zones. It also materializes online.values for attendance and delivery on due zones. A direct value iteration plus an early break on first attendee is a straightforward candidate for the *read-only attendance* pass. Keep mutation-capable delivery safe. Defer more complicated weather indices until timings justify them. [Weather](/home/hampus/dmangos/source/dmangos/world/context.d:215) [called in world phase](/home/hampus/dmangos/source/dmangos/world/context.d:6334)
- The network reads into 4 KiB of stack memory. WorldSession copies the chunk into a GC array and drops the array when completely drained, so a run of complete small frames reacquires storage. Scalar ByteReader operations consume bytes from slices; readString/.idup and byte/blob .dup or array decoding are separate ownership costs, generally correct for values that survive dispatch. Per-session input reuse is an experiment only after measuring parse allocation under fragmentation, coalescing, and realistic traffic. Never overwrite bytes retained by a deferred handler. Keep existing outbox adoption, partial-send tracking, connection limits and buffer return. [Read](/home/hampus/dmangos/source/dmangos/net/server.d:466) [framing](/home/hampus/dmangos/source/dmangos/world/session.d:318) [borrowed bytes and owned text](/home/hampus/dmangos/source/dmangos/bytes.d:199) [blob](/home/hampus/dmangos/source/dmangos/serialization.d:165) [output adoption](/home/hampus/dmangos/source/dmangos/net/server.d:355) [return](/home/hampus/dmangos/source/dmangos/net/server.d:495)
- Installation-specific results by project authors: 500 bots, seeded crowd, 430→103 KB per tick and 3→0 collections in the measured minute with visibility scratch reuse; spread 240→215 KB and 1→1. The same runs saw busy time 7.5→7.9% and 10.5→11.2%, so avoid calling it a CPU win. Earlier combined one marking thread plus freezing 26 MiB reduced measured crowd pause 55.6→16.4 ms and spread 71.6→37.7 ms; their table does not isolate the two effects. Save stress reduced worst-interval tick p99 10.31→1.02 ms using a writer. Most recent 500-bot crowd result after the cheap alive query was tick 0.39 ms, 8.3–8.4% busy in release-fast; it leaves an unresolved busy-time rise against the previous evening. Different builds/scenarios are not a time series to combine. - GcSnapshot combines process collection and pause statistics with allocation by the **calling thread**; per-tick divides its total interval allocation by the number of ticks, so packet handling between ticks contributes and writer allocations are excluded. Measure before/after delta in mapsPhase, receive, and visibility with the existing counter. Repeat seed 7 crowd/spread, fixed compiler and same optimization level; report GC bytes, pause distribution, tick/loop tails, ping, packet counts, RSS and queue depth. A minute with no collections puts no upper bound on long-run pause. Add a retained-heap/multi-hour check only if evaluating high-water buffers or arena changes. Keep peak sizes bounded by connection counts and output backlog; retain large buffers selectively only if RSS warrants. - Writer encodes independent owned bytes, producers wait at a bounded queue, superseded writes are marked and a worker transfers an entire batch under a short lock before journal I/O. Keep ordering, replay, and fencing. Deliberate backpressure can stall the game thread when DB is persistently behind; evaluate this against the owner's permitted stall and loss policy. Do not silently substitute dropping, unconditional async, or borrowing a gameplay object's mutable buffer. ### Gaps

No fresh live crowd or database regression was run; the normal benchmark harness revives bots and mutates a shared DB. The check used an isolated build and a controlled allocation experiment. Ask for representative session mix (raid combat, movement, spread, traffic bursts), production RSS/tail limits, machine/core count, marking options, DB stall policy and permitted downtime. Avoid pools for entities, SIMD packet parsers, whole-tick @nogc or disabling GC on available evidence.

## Which existing design and language choices should stay?

### Takeaway

The repository is already idiomatic D in the places where a mechanical C++ port would ordinarily be most conspicuous. The relevant comparators are measured behavior, ownership and local API clarity.

### Cited findings

- Keep D modules and selective imports, including local optional dependencies and UFCS on read-only query chains. The short filter/array at a session lookup exposes the materialization directly; no header/implementation split is needed. Keep source-level interfaces where test doubles and clustered implementations carry identity. [Session lookup](/home/hampus/dmangos/source/dmangos/world/context.d:6164) [Character](/home/hampus/dmangos/source/dmangos/world/character.d:107) [Map](/home/hampus/dmangos/source/dmangos/world/map.d:378)
- Keep struct packet values, slice reader/writer, fixed arrays for wire widths, and noncopyable UpdateValues with owned array state. Avoid a class hierarchy or smart pointers for packets. Use const for borrowed views and owned immutable strings at persistence boundaries; Vector3's return-qualified inout indexing preserves caller qualifiers without duplication. [ByteReader](/home/hampus/dmangos/source/dmangos/bytes.d:144) [UpdateValues](/home/hampus/dmangos/source/dmangos/world/objects.d:122) [inout](/home/hampus/dmangos/source/dmangos/vmap/math.d:43)
- Keep leaf @safe default and pure/nothrow/@nogc on small arithmetic, cursor properties and timers. Keep input truncation as explicit parse exceptions, with contracts for internal preconditions and cursor invariant. Growing arrays/throwing a freshly allocated exception make wholesale @nogc a different API. No need to blanket-mark gameplay @trusted to make attribute checking pass. Scoped delegates and nested functions express local control clearly (timed phase and player fault isolation); benchmark the actual closures before changing them. Lazy StaticMap.get mirrors AA fallback and short-circuits its evaluation. Keep scope(exit) for borrowed scratch and lock release. - Keep packet UDAs with static foreach/traits, template constraints for wire scalars, compile-time wire sizing and route generation. These enforce duplicate cases and bind opcodes/state to their handling methods. Keep regular switch with unknown-opcode handling on the wire, validated enum values and exhaustive final switch once ownership/type boundaries make enumerators closed. Foreach over the ready batch and movers exposes order and mutation behavior; default D control flow avoids silent case fallthrough. Keep alias offset this on update-field descriptors (index arithmetic) and handle wrappers exposing one capability via alias inner this; avoid layering further implicit conversions. - Keep Character's named mixins (56 at lines 808–863) to colocate behavior by domain.
