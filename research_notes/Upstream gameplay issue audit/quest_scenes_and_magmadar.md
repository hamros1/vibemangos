# Quest scenes and Magmadar follow-up

## Jeziba introduces the book at quest acceptance

Classic-DB contains Jeziba `10976`, catalogue `176192` and BroadcastText `6332`. Quest `5164` had no start script. vMaNGOS's fix gives the verified sequence at one, two, three and five seconds. The DMaNGOS overlay faces the actual nearby catalogue, sends the original line to the accepting client, points, and restores the spawn's facing. The database script now wakes sleepers when a turn starts so the spline can finish and the later command can run. [vMaNGOS #3587](https://github.com/vmangos/core/issues/3587), [vMaNGOS migration](https://github.com/vmangos/core/blob/d15f7606a2c9f4a9c761069123b14319d0e1954f/sql/migrations/20261107212919_world.sql#L58-L66), [linked Classic recording](https://youtu.be/3q6K8nRMtWc?t=598)

## Joseph starts the reunion after the battle

Quest `5942` is awarded after `5721` and uses Joseph's Key at Joseph's Chest. Classic-DB already supplies all seven reunion lines in BroadcastText `7397` through `7403`. It also supplies Joseph's gossip script for the `5721` objective. No native script or database event started the prerequisite battle from Relic Bundle `177526`, so Joseph had no route into the world. The implementation starts that reenactment from the actual relic object and stages the defender waves, Horgus and Davil, and Marduk's corruption of Captain Redpath. Defeating Corrupted Redpath brings Joseph and Davil Crokford. Joseph's ordinary gossip awards the existing quest credit and starts the reunion's 30-second wait, followed by the walk, dialogue and Pamela's move. The client can then turn in the battle to Pamela and collect the chest reward. [vMaNGOS #2999](https://github.com/vmangos/core/issues/2999), [vMaNGOS battle and reunion source](https://github.com/vmangos/core/blob/development/src/scripts/eastern_kingdoms/eastern_plaguelands/eastern_plaguelands.cpp#L920-L1727), [original player accounts of the battle](https://www.wowhead.com/classic/quest=5721/the-battle-of-darrowshire), [Classic recording one](https://youtu.be/nef_hw-23nk?t=962), [Classic recording two](https://youtu.be/mgsMh8klozg?t=491)

## Magmadar shares one Lava Bomb timer

vMaNGOS #2648 links two 2005 fights and reports one bomb per cadence. TrinityCore's independently published implementation notes one spell every 12–15 seconds and uncertainty about when the boss picks each variant. The CMaNGOS commit that introduced two separate timers records uncertainty about timing. DMaNGOS now uses one 12–15 second recurring timer while keeping its existing mana and non-mana spell associations as the best available model for this client. The original cadence is corroborated by implementation research and a player report. Actual raid-wide cast data and the original probability of choosing either target class remain unverified. [vMaNGOS #2648](https://github.com/vmangos/core/issues/2648), [TrinityCore timing notes](https://trinitycore.net/d0/d26/boss__magmadar_8cpp_source), [CMaNGOS split-spell commit](https://github.com/cmangos/mangos-classic/commit/f1d799b7299dd46fc3311e9b4209bf4542b814e9)

The two original spells are dummy effects in local Classic-DB. Neither had a binding, so the cast left no fire. The DMaNGOS effect now places trap `177704` on the hit player's position and uses the two variants' 30-second and 60-second lifetimes. The trap applies the stock Conflagration spell to nearby players while active. [vMaNGOS Lava Bomb spell routing](https://github.com/vmangos/core/commit/21c6bb5b1be14e898cb1b06c3e738885688f38d4), [Classic raid strategy](https://www.wowhead.com/classic/guide/magmadar-molten-core-strategy-wow-classic)

## Database installation

Fresh installations apply the world fixes after importing Classic-DB. Existing installations can run `tools/database.sh apply-world-fixes` with their MariaDB connection options before restarting. The overlay is safe to reapply and preserves populated script bindings. The initial stock-archive install and the reapply command were verified on a private MariaDB database. The real-world and raid tests were run with that patched database.
