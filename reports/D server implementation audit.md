# Keep the world model and tighten its memory boundaries

**Keep the server architecture. Fix the contracts on frozen-row editing, plain-data decoding and script tick dispatch first.** In each case the implementation accepts a broader set of inputs than its memory or type assumptions support. The current callers examined generally respect those assumptions. For performance, the best next measurement is how much the player bookkeeping allocates inside the maps phase. The repository already has stronger evidence for its existing visibility scratch buffers and write-behind worker than any external D project supplies for replacing them. ## Three interfaces admit unsupported operations

| Priority and confidence | Source-level finding | Smallest change that preserves behavior |
|---|---|---|
| High · high confidence | **Frozen rows.** Recursive freezing puts nested arrays in separate, unscanned native storage. `edit` registers only the outer row with the GC and returns a mutable pointer. An edit that installs a GC reference inside a nested arena allocation leaves that reference outside the registered range. The existing direct-field replacement test covers the outer row. No production instance of the nested edit was demonstrated. [Copy](/home/hampus/dmangos/source/dmangos/frozen.d:130) · [Edit](/home/hampus/dmangos/source/dmangos/frozen.d:319) · [Test](/home/hampus/dmangos/source/dmangos/frozen.d:497) | Establish which row shapes actually need deep editing. Restrict edit access to supported shapes if adequate. Otherwise place the editable reference-bearing children in traced storage before exposing them. Preserve issued row addresses. Make raw allocation/copy helpers private alongside this correction. |
| High · high confidence | **Plain-data decoder.** A public `@trusted` template takes arbitrary `ref T`, then writes through a pointer to `Unqual!T`. Recursion applies the same treatment to qualified fields. Dynamic-array lengths are bounded against remaining bytes as though every element occupied one byte. [Decoder](/home/hampus/dmangos/source/dmangos/plaindata.d:92) · [Length check](/home/hampus/dmangos/source/dmangos/plaindata.d:115) · [Service caller](/home/hampus/dmangos/source/dmangos/cluster/services.d:252) | Have the decoder initialize a fresh owned value, or constrain public writable destinations and isolate fresh qualified-field initialization privately. For fixed-width elements validate against remaining encoded bytes per element before allocation. Verify existing log/service bytes round-trip and unsupported destinations fail to compile. |
| High · high confidence | **Script ticks.** A registered thunk knows its context type. The handle selects the thunk, while a separate generic argument supplies the address of the context. Event dispatch checks the correspondence. Tick dispatch omits that check. Observed ordinary callers supplied matching types. [Tick](/home/hampus/dmangos/source/dmangos/script/registry.d:614) · [Thunk](/home/hampus/dmangos/source/dmangos/script/registry.d:435) · [Caller](/home/hampus/dmangos/source/dmangos/world/instancescripting.d:163) | Enforce the existing kind/context relationship before the erased call, using the event path as precedent. | Medium · high confidence | **Free-slot lookup.** The public slot and generation can describe a free slot. Lookup checks matching generation and bounds, even though `holds` also checks occupancy. Removal relies on lookup to decide whether it should change the free list and live count. [Lookup](/home/hampus/dmangos/source/dmangos/store.d:56) · [Occupancy](/home/hampus/dmangos/source/dmangos/store.d:69) · [Removal](/home/hampus/dmangos/source/dmangos/store.d:81) | Require `holds(r.slot)` and the matching generation. | Medium · high confidence | **Native tile construction.** Two throwing C++ array allocations occur after manual resources have been acquired in a function with an error-code ABI. | Low · high confidence | **Maintenance timer.** The server permits a null maintenance callback. After its interval expires, the timeout remains zero because the timestamp advances only when the callback exists. Both shipped mains supply one. [Constructor](/home/hampus/dmangos/source/dmangos/net/server.d:224) · [Deadline](/home/hampus/dmangos/source/dmangos/net/server.d:291) | Advance the deadline independently, or omit it from the timeout calculation when maintenance is disabled. |

## Most pointers express ownership or optional access clearly

The [pointer usage table](</home/hampus/dmangos/reports/D server pointer inventory.md>) is part of this audit. A syntax-tree walk covered **326 tracked D files**, including tests and tools, with zero parse errors. The table records **3,173 source lines in 191 files** (190 D files with sites plus the C++ shim), including **100 pointer-return declarations**. For every inventoried source line, the file heading, line, operation and verdict key give its purpose, verdict, alternative and confidence. The appendix separately catalogs pointers returned across function boundaries. It includes explicit pointer types/casts, address-taking, dereferences, slice `.ptr`, AA `in` and `!in`, typed callbacks, generated MariaDB signatures, selected inferred handles/arithmetic and the project-owned C++ navigation shim. It excludes upstream Recast/Detour code, hidden compiler indirections, implicit array decay and repeated implicit use of variables already listed. This is source coverage. Proving every borrow valid in every template instantiation would require stronger lifetime contracts.

## Measure the maps phase before changing its snapshots

| Path | Evidence and interpretation | Decision |
|---|---|---|
| Visibility and spatial queries | The project's seeded 500-bot, 60-second run recorded crowd allocation falling from **430 to 103 KB/tick** with scratch reuse. Collections fell from 3 to 0. Spread fell from 240 to 215 KB/tick and had one collection in each run. Busy time rose slightly in both comparisons. In the investigation preceding this change, 87% of sampled main-loop allocation was in packet handling. [Experiment](/home/hampus/dmangos/docs/BENCHMARKS.md:384) | Keep map-owned visibility bits and borrowed query lists. Treat this as measured allocation and GC improvement. The data do not establish a CPU win or predict a long-run pause ceiling. |
| Player tick | Maps and instance maps materialize `.values`. Each populated map builds a player list. The fallback walk snapshots `online.values`. The maps phase clears and refills its updated-player AA. An isolated, warmed DMD 2.114.0 x86-64 `-O -release` experiment with 500 entries and 100 iterations measured **8,000 GC bytes per clear/refill** and **4,096 per class-reference AA `.values`**. Application-wide savings remain unmeasured. [Phase](/home/hampus/dmangos/source/dmangos/world/context.d:6243) · [Player snapshot](/home/hampus/dmangos/source/dmangos/world/map.d:1876) · [Experiment notes](</home/hampus/dmangos/research_notes/D server implementation audit/implementation.md>) | Measure mapsPhase with actual map and player counts. If material, reuse owner-held snapshot storage and clear old references. Preserve once-per-tick updates, callback order, logout, teleport and between-map handling. Direct iteration through mutating callbacks loses those guarantees. |
| Network receive and serialization | The server reads into a 4 KiB stack buffer. WorldSession appends bytes and discards its array when drained. Scalar reads borrow slices, while owned strings, blob duplicates and decoded arrays have different lifetimes. The outbound path already adopts buffers and retains them across partial sends. [Read](/home/hampus/dmangos/source/dmangos/net/server.d:466) · [Frames](/home/hampus/dmangos/source/dmangos/world/session.d:318) · [Bytes](/home/hampus/dmangos/source/dmangos/bytes.d:199) · [Blob](/home/hampus/dmangos/source/dmangos/serialization.d:165) · [Send](/home/hampus/dmangos/source/dmangos/net/server.d:355) | Measure allocations by packet mix, including fragmented and coalesced traffic. Try a reusable per-session receive buffer only if retained-byte ownership is clear. Check aggregate RSS at peak connection count and isolate retained payloads before reusing bytes. |
| Weather and loot | Weather snapshots zone keys for removals, and materializes online players to determine attendance. Loot group selection allocates pointer arrays for shuffling. [Weather](/home/hampus/dmangos/source/dmangos/world/context.d:215) · [Loot](/home/hampus/dmangos/source/dmangos/world/loot.d:621) | The read-only attendance scan can iterate the AA directly and stop at the first attendee. Preserve mutation-safe delivery. Try loot scratch only for a measured cost, retaining draw count, order, conditions and distribution. |
| Persistence and backpressure | The writer owns encoded work, bounds its queue, coalesces superseded writes and moves a batch out under lock. The project's save stress test reported worst-interval tick p99 falling from **10.31 to 1.02 ms**. A slow DB can still stall the producer at the bounded queue. [Queue](/home/hampus/dmangos/source/dmangos/world/writebehind.d:309) · [Batch](/home/hampus/dmangos/source/dmangos/world/writebehind.d:427) · [Measurement](/home/hampus/dmangos/docs/BENCHMARKS.md:290) | Keep the worker, ordering, lease fencing, replay and bounded ownership. Measure sustained queue depth and enqueue wait before changing any backpressure policy. |
| Frozen data and GC tuning | Earlier project runs combined one marking thread with freezing 26 MiB of data. Measured crowd pause fell from 55.6 to 16.4 ms and spread from 71.6 to 37.7 ms. These runs changed both variables. The November 20 release-fast crowd run reported 0.39 ms tick and 8.3–8.4% busy after a narrow alive-query change. The remaining rise in loop busy time was unresolved. [GC comparison](/home/hampus/dmangos/docs/BENCHMARKS.md:307) · [Latest run](/home/hampus/dmangos/docs/BENCHMARKS.md:492) | Preserve the measured configuration as baseline. To attribute changes, vary one setting at a time under the same compiler, host, workload and duration. |

**Measurement order.** Start with warmed seed-7 crowd and spread runs under matching release settings. Take thread-local byte-counter deltas around mapsPhase, receive/dispatch and visibility separately. The current per-tick number divides an interval's loop allocation by tick count, so it includes inter-tick packet work and excludes the writer's allocations. Collect tick and loop p95/p99, ping, CPU busy time, collections, total and maximum pause, RSS, counts of delivered packets and queue depth. Compare repeated runs and extend the duration when a run sees few collections. Compare retained heap after peaks if scratch or arena lifetime changes. A cumulative maximum cannot yield a pause percentile. [Current metrics](/home/hampus/dmangos/source/dmangos/metrics.d:108) · [Denominator](/home/hampus/dmangos/source/dmangos/metrics.d:149) · [GC statistics](https://dlang.org/library/core/memory/gc.profile_stats.html)

**Allocation policy.** Keep stack storage for bounded immediate operations, GC-backed ownership for independently lived values, and selective reusable buffers where the project can show the benefit. An entity pool adds reset rules and stale-handle risks. A general packet arena introduces a lifetime shared across consumers and queues. Whole-tick `@nogc` would force changes to normal error paths and genuinely owned data. The evidence favors none of these rewrites. Add `@nogc` to a bounded leaf when the compiler can enforce a promise useful to a caller. A function with that attribute can still allocate natively or take unbounded time. [Byte reader](/home/hampus/dmangos/source/dmangos/bytes.d:144) · [Timer](/home/hampus/dmangos/source/dmangos/timer.d:29) · [DMD buffer implementation](https://github.com/dlang/dmd/blob/bc9a7a27e3608bf4ae0940a28fec9288cf5a726f/compiler/src/dmd/common/outbuffer.d#L144-L203)
